# Shorts Agent · Polza AI

Автономный Telegram-бот для производства вертикальных черновиков 9:16. Пользователь выбирает «История», «Факт» или «Подборка» и пишет тему. Агент через Polza AI строит сценарий, выбирает один из трёх хуков, находит готовые фото Pexels и генерирует русскую озвучку. FFmpeg добавляет движение и крупные экранные фразы; MP4 возвращается в Telegram на просмотр. Ничего само в публичные каналы не отправляется.

## Первые три секунды

- Первая реплика содержит не более семи слов и начинает действие: конкретный предмет, конфликт или странный исход. Нет логотипа, заставки и «а вы знали».
- Агент предлагает три угла, выбирает один, проверяет длину хука перед подбором фото. Первая надпись — максимум четыре слова. Озвучка начинается на первом кадре.
- Кадр 0 показывает предмет вопроса. Каждая следующая сцена должна раскрыть новую деталь за 3–6 секунд. Последняя даёт ответ. Честный конкретный сюжет важнее искусственного кликбейта.

Пример по принципу присланного видео: вместо «Пушкин — история за минуту» первый кадр может показать письмо над горящей свечой и фразу «Его письмо не должно было дойти». Затем каждая сцена объясняет одно событие. Это только пример драматургии, не историческое утверждение и не готовый сценарий.

## Производственная схема

```
Telegram → очередь (1 ролик одновременно, до 4 ожидают)
         → Polza Chat Completions (JSON сценария и visual bible)
         → Pexels Search API (готовые вертикальные фото, без платы за генерацию)
         → Polza Audio Speech (base64 MP3 на каждую сцену)
         → FFmpeg (1080×1920, движения, надписи, звук)
         → личное превью в Telegram
```

Один worker предохраняет CPU Railway и баланс от нескольких одновременных рендеров. Очередь находится в памяти и теряется при рестарте; для постоянного потока понадобится Postgres/Redis, записи статусов и отдельный worker. Код находится в отдельном репозитории и запускается отдельным Railway service, чтобы долгий рендер не мешал работающему Content OS.

## Запуск на Railway

Создайте Railway service из репозитория `mfievmkmkm/shortsss`. Root Directory оставьте `/`: Dockerfile находится в корне. Для polling нужен один инстанс, без публичного домена.

Variables:

```env
TELEGRAM_BOT_TOKEN=токен_нового_бота
POLZA_API_KEY=ключ_polza
PEXELS_API_KEY=ключ_фотостока_Pexels
ALLOWED_USER_IDS=ваш_числовой_Telegram_ID
TEXT_MODEL=openai/gpt-4o-mini
VOICE_MODEL=openai/gpt-4o-mini-tts
VOICE=alloy
```

`ALLOWED_USER_IDS` обязателен; несколько ID пишутся через запятую. Ключи храните только в Railway Variables, не в GitHub. Polza используется для текста (`/api/v1/chat/completions`) и голоса (`/api/v1/audio/speech`); speech возвращает JSON с base64 аудио. Изображения берутся из готового каталога Pexels, ключ Pexels обязателен. Фото бесплатно в рамках условий Pexels API; ссылки на исходные фото бот присылает рядом с роликом. Платными остаются текст и голос Polza, а также Railway.

Локально: `python3 shorts_bot.py` при наличии FFmpeg, FFprobe и TTF шрифта с кириллицей. Старт через `/start`.

## Что улучшать дальше

1. Полноценный редактор: изменить хук, переписать сцену, заменить кадр, превью первых трёх секунд до полного рендера.
2. Источники и фактчекинг: для новостей/истории прикладывать проверяемые ссылки и даты в служебной карточке. Сейчас агент работает с темой, **не ищет источники сам**; нельзя считать его факты проверенными.
3. Свой медиаархив: права на B-roll, единый голос/персонаж, фоновая музыка с лицензией, аудиоэффекты, субтитры по словам, темп переходов и A/B версия первого кадра.
4. Метрики: отдельно измерять удержание 3-й секунды, досмотр и сохранения после ручной публикации. Перестраивать хуки по этим данным, а не по самоуверенной оценке модели.
5. После подтверждения превью: экспорт под Shorts/Reels/TikTok и согласованная публикация через официальные интеграции, с отдельными правами доступа.

Ограничения MVP: последовательный синтез голоса по сценам может звучать неоднородно, фотосток не гарантирует точных кадров исторических лиц и единого героя между сценами, музыкальной дорожки и видеогенерации здесь нет. «Живость» строится на сценарии, голосе, движении и монтажном ритме; качество нужно оценить на реальных роликах и поправить после просмотра.
